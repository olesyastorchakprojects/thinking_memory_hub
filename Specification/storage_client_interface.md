# Storage Client Interface

## 1. Purpose

This document defines the complete storage client artifact used by the thinking memory MCP server.

This document is the source of truth for:

- `app/memory_server/storage_client.py`

This document uses:

- `Specification/data_contracts.md`
- `db/schema.sql`

## 2. Ownership Boundary

The storage client owns:

- PostgreSQL connectivity
- SQL execution
- transactions
- persistence of notes
- persistence of tags
- persistence of note-to-tag links
- aggregation of tags from matching notes

The storage client does not own:

- MCP transport
- MCP tool registration
- JSON-compatible tool payload validation
- note classification
- tag generation
- LLM calls

## 3. Public Artifact

The storage client artifact consists of exactly one public class:

- `StorageClient`

The `StorageClient` class must be defined in:

- `app/memory_server/storage_client.py`

## 4. Required Imports And Dependencies

The storage client must use:

- psycopg
- psycopg_pool
- the typed models defined in `app/memory_server/models.py`
- the error types defined in `app/memory_server/errors.py`

## 5. Public Class Contract

### 5.1 `StorageClient`

The module must define exactly this public class:

```python
class StorageClient:
    def __init__(self, database_url: str) -> None:
        ...

    async def open(self) -> None:
        ...

    async def close(self) -> None:
        ...

    async def create_note(self, request: NoteCreateRequest) -> NoteRecord:
        ...

    async def search_notes(self, request: NoteSearchRequest) -> NoteList:
        ...

    async def update_note(self, request: NoteUpdateRequest) -> NoteRecord:
        ...

    async def search_tags(self, request: TagSearchRequest) -> TagList:
        ...
```

Rules:

- `database_url` is the only constructor argument
- `database_url` must be used for PostgreSQL connections
- the class must create and own a PostgreSQL async connection pool
- the pool type must be `AsyncConnectionPool`
- `open()` must initialize the async connection pool
- `close()` must close the async connection pool
- all public methods must accept typed request objects
- all public methods must return typed response objects
- this class must not expose raw SQL strings as public API
- this class must not return raw psycopg rows

## 5.2 Required psycopg Async API Shape

The storage client must use the psycopg async cursor API.

Rules:

- SQL execution must happen through `async with conn.cursor(...) as cur`
- row-producing queries must use `row_factory=dict_row`
- query execution must use `await cur.execute(sql, params)`
- single-row reads must use `await cur.fetchone()`
- multi-row reads must use `await cur.fetchall()`
- the implementation must not call invented connection-level helpers such as `conn.fetch()` or `conn.fetchone()`
- transactions must use `async with conn.transaction():`
- connection acquisition must use `async with pool.connection() as conn:`

## 6. Method Contracts

### 6.1 `create_note`

Signature:

```python
async def create_note(self, request: NoteCreateRequest) -> NoteRecord:
    ...
```

Rules:

- `request` must satisfy `NoteCreateRequest`
- the method must create exactly one row in `notes`
- the method must ensure that every stored tag exists in `tags`
- the method must create one row in `note_tags` per stored tag attached to the note
- the method must return exactly one `NoteRecord`
- the returned `NoteRecord.id` must be the UUID generated by PostgreSQL
- the returned `NoteRecord.raw_text` must equal `request.raw_text`
- the returned `NoteRecord.normalized_text` must equal `request.normalized_text`
- the returned `NoteRecord.note_kind` must equal `request.note_kind`
- the returned `NoteRecord.source_ref` must equal `request.source_ref`
- the returned `NoteRecord.created_at` must equal `request.created_at`
- the returned `NoteRecord.updated_at` must equal the stored `updated_at`
- the returned `NoteRecord.tags` must equal the stored tag set for the note
- when `request.source_ref` violates a uniqueness rule, the method must raise `StorageConflictError`

### 6.2 `search_notes`

Signature:

```python
async def search_notes(self, request: NoteSearchRequest) -> NoteList:
    ...
```

Rules:

- `request` must satisfy `NoteSearchRequest`
- the method must return exactly one `NoteList`
- the returned list must contain only notes matching the full request
- all present filters must apply together
- `query`, when present, must search `notes.normalized_text`
- `query`, when present, must use PostgreSQL `pg_trgm`
- `query`, when present, must filter with the `%` operator against `notes.normalized_text`
- `query`, when present, must be combined with all present filters
- `query`, when present, must contribute exactly two SQL bind values:
  - one bind value for `similarity(notes.normalized_text, query)`
  - one bind value for `notes.normalized_text % query`
- `tags`, when present, must use `tag_match_mode`
- when `tags` is present and `tag_match_mode` is absent, the method must raise `StorageClientError`
- `time_range`, when present, must filter `notes.created_at`
- `note_kinds`, when present, must filter `notes.note_kind`
- `source_refs`, when present, must filter `notes.source_ref`
- when `query` is present, the returned list must be ordered first by `similarity(notes.normalized_text, query)` descending
- when `query` is present, `request.sort` must be applied as the created-at tie-breaker
- when `query` is absent, the returned list must be sorted according to `request.sort`
- the returned list length must be less than or equal to `request.limit`
- `request.offset` must skip the first matching notes before returning items
- every returned item must be a fully populated `NoteRecord`
- every returned item must include the full stored tag set of that note
- bind parameters for `LIMIT` and `OFFSET` must be appended last
- the SQL placeholder count must match the final bound parameter count exactly

### 6.3 `update_note`

Signature:

```python
async def update_note(self, request: NoteUpdateRequest) -> NoteRecord:
    ...
```

Rules:

- `request` must satisfy `NoteUpdateRequest`
- the method must update exactly one existing note identified by `request.note_id`
- all operations in `request.operations` must be applied atomically
- when any operation is invalid, the method must fail and no change must be persisted
- when `request.note_id` does not exist, the method must raise `StorageNotFoundError`
- `set_note_kind` must replace the stored `note_kind`
- `set_normalized_text` must replace the stored `normalized_text`
- `replace_tags` must replace the full stored tag set
- `add_tags` must add tags to the existing stored tag set
- `remove_tags` must remove tags from the existing stored tag set
- when tags are added or replaced, the method must ensure that every stored tag exists in `tags`
- the method must return exactly one updated `NoteRecord`
- the returned `NoteRecord.id` must equal `request.note_id`
- the returned `NoteRecord.updated_at` must be greater than or equal to the previous stored `updated_at`

### 6.4 `search_tags`

Signature:

```python
async def search_tags(self, request: TagSearchRequest) -> TagList:
    ...
```

Rules:

- `request` must satisfy `TagSearchRequest`
- the method must return exactly one `TagList`
- the returned tag set must be derived from notes matching the full request
- all present filters must apply together
- `query`, when present, must filter tag names
- `time_range`, when present, must restrict the note set used for tag aggregation
- `note_kinds`, when present, must restrict the note set used for tag aggregation
- `source_refs`, when present, must restrict the note set used for tag aggregation
- every returned item must be a `TagSearchResult`
- `TagSearchResult.usage_count` must equal the number of matching notes that contain the tag
- the returned list must be sorted according to `request.sort`
- the returned list length must be less than or equal to `request.limit`
- `request.offset` must skip the first matching tag results before returning items

## 7. Transaction Contract

The storage client must use PostgreSQL transactions.

Rules:

- public methods must acquire connections from the pool
- transactions must use pooled connections
- public methods must use async PostgreSQL operations
- `create_note` must persist note row, tag rows, and note-to-tag rows in one transaction
- `update_note` must apply all requested note and tag changes in one transaction
- partial persistence is forbidden for `create_note`
- partial persistence is forbidden for `update_note`

## 8. SQL Mapping Contract

The storage client must use the schema defined in `db/schema.sql`.

Required table ownership:

- note rows are stored in `notes`
- tag rows are stored in `tags`
- note-to-tag links are stored in `note_tags`

Field mapping:

- `NoteRecord.id` maps to `notes.id`
- `NoteRecord.raw_text` maps to `notes.raw_text`
- `NoteRecord.normalized_text` maps to `notes.normalized_text`
- `NoteRecord.note_kind` maps to `notes.note_kind`
- `NoteRecord.source_ref` maps to `notes.source_ref`
- `NoteRecord.created_at` maps to `notes.created_at`
- `NoteRecord.updated_at` maps to `notes.updated_at`
- `NoteRecord.tags` maps to `tags.name` values joined through `note_tags`

## 9. Error Contract

The storage client must use these error types:

- `StorageClientError`
- `StorageNotFoundError`
- `StorageConflictError`

Rules:

- `StorageNotFoundError` must be raised when a requested note does not exist
- `StorageConflictError` must be raised when a uniqueness constraint is violated
- storage failures not covered by a more specific storage error must raise `StorageClientError`

## 10. Data Contract Bindings

The storage client uses exactly these request and response types:

- `create_note`
  - input: `NoteCreateRequest`
  - output: `NoteRecord`
- `search_notes`
  - input: `NoteSearchRequest`
  - output: `NoteList`
- `update_note`
  - input: `NoteUpdateRequest`
  - output: `NoteRecord`
- `search_tags`
  - input: `TagSearchRequest`
  - output: `TagList`

## 11. Test Isolation Rules

Tests for the storage client must not connect to a live PostgreSQL instance.

These tests are unit-level contract tests for `StorageClient`.

Rules:

- unit tests must use mocks, fakes, or stubs
- unit tests must not depend on a running Docker container
- unit tests must not depend on an externally provisioned database
- SQL execution boundaries must be isolated behind test doubles where needed
- test doubles for psycopg must mirror the real async API shape used by the implementation:
  - `pool.connection()`
  - `conn.transaction()`
  - `conn.cursor()`
  - `cur.execute()`
  - `cur.fetchone()`
  - `cur.fetchall()`
- tests must not mock non-existent psycopg helpers such as `conn.fetch()` or `conn.fetchone()`

These rules apply to the unit test module:

- `tests/test_storage_client.py`

## 12. Integration Test Rules

The storage client must also be covered by integration tests against a real PostgreSQL database.

Rules:

- integration tests must live under `tests/integration/`
- integration tests are separate from the unit test suite
- integration tests must be marked with `pytest.mark.integration`
- integration tests must use `TEST_DATABASE_URL`
- when `TEST_DATABASE_URL` is unset, integration test setup must call `pytest.skip(...)`
- when `TEST_DATABASE_URL` is set but the database is unreachable, integration tests must fail
- integration tests may use the local Docker PostgreSQL container
- integration tests must target a dedicated integration-test database
- integration tests must use the schema from `db/schema.sql`
- integration tests must not mock the storage layer
- integration tests must apply `db/schema.sql` to the test database before test execution
- integration tests must isolate data with unique `source_ref` values
- integration tests must remove inserted test records during fixture teardown
- integration tests must not rely on transaction rollback as the primary isolation strategy
- integration tests must validate real SQL behavior for:
  - note creation
  - normalized-text search
  - atomic updates
  - tag aggregation
  - `source_ref` uniqueness conflicts
